# Архитектура DualVPN

```text
LAN/Wi-Fi → firewall zone dualvpn → wg0 ИЛИ awg0 → VPN-сервер → интернет
VPN endpoint → отдельный /32 → исходный transport interface → провайдер
```

`AllowedIPs=0.0.0.0/0` определяет допустимый трафик peer, но у обоих peer
`route_allowed_ips=0`. Иначе netifd создаст два конкурирующих default route. Маршрут
по умолчанию контролирует только `vpn-apply-route`.

VPN default использует metric 10, транспорт — настраиваемый metric 100. Без этого
обычный WAN с metric 0 продолжал бы выигрывать маршрут, несмотря на поднятый VPN.

Перед переключением `vpn-switch`:

1. проверяет, что транспорт поднят;
2. запускает optional pre-VPN hook;
3. поднимает целевой интерфейс;
4. временно направляет `PROBE_IP/32` через него;
5. ждёт handshake и ping;
6. только после успеха меняет default route и сохраняет режим.

Host route endpoint всегда идёт через L3-device транспорта и предотвращает
заворачивание управляющих UDP-пакетов VPN внутрь самого туннеля.

Firewall-зона `dualvpn` содержит оба интерфейса, masquerading и MTU fix. Разрешено
`LAN_ZONE → dualvpn`; прямой forwarding в `TRANSPORT_ZONE` отключается. Это kill
switch, а не гарантия против всех возможных policy rules, пользовательских nftables
или IPv6: дополнительные правила надо проверять отдельно.

Автоматический failover отключён. На мобильной сети краткая потеря пакетов обычна,
и агрессивный watchdog способен создать постоянное переключение. Этот проект даёт
предсказуемый ручной механизм и одноразовое восстановление сохранённого режима.

Переключение не выполняет `ifdown` резервного интерфейса. Поэтому оба туннеля могут
иметь свежий handshake и передавать служебные пакеты. Активный режим — это интерфейс
в `ip -4 route show default`, а не единственный доступный VPN. Например, при
`default dev wg0 metric 10` SSH к VPN-адресу `awg0` продолжает работать и даёт
резервный канал управления.

Downstream-исключения разрешают клиентам LAN отправлять UDP только к literal IPv4
endpoint/port напрямую в transport zone. Для hostname правило автоматически не
создаётся, поскольку его адрес может измениться.

IPv6 по умолчанию выключен. Включайте `ENABLE_IPV6=1` только если оба peer содержат
`::/0`, сервер маршрутизирует IPv6, firewall проверен и endpoint-транспорт не создаёт
обход VPN.
